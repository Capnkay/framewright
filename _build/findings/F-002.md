## What is wrong

Six file paths declared in `_build/tasks.json` for the Phase 1 client tasks do not match the
files `T-000` actually committed, and the `doneWhen` conditions for four of those tasks are
**already satisfied** by the existing files.

| Task | Board declares | On disk, and imported by the passing tests |
|---|---|---|
| T-008 | `client/src/store/cmsSlice.js` | `client/src/redux/cmsSlice.js` |
| T-009 | `client/src/store/fetchElementsByIds.js` | `client/src/redux/fetchElementsByIds.js` |
| T-010 | `client/src/utils/getSectionTextContrastClass.js` | `client/src/utils/sectionContrast.js` |
| T-011, T-012, T-014 | `client/src/sections/HeroSection.jsx` | `client/src/sections/generated/HeroSection.jsx` |
| T-012 | `client/src/utils/getHtml.js` | `client/src/utils/html.js` |
| T-013 | `client/src/utils/image.js` | matches — the only one that does |

## Where

`_build/tasks.json`, tasks T-008 through T-014 and T-050, read against `git ls-files client/`
and the import list in `tests/golden.test.mjs`.

## Why it matters

**1. Building to the board literally orphans the tested code.** `tests/golden.test.mjs`
imports the on-disk paths. A person claiming T-008 and "writing the cms Redux slice" at
`client/src/store/cmsSlice.js` produces a second slice that no test covers, while the one
that *is* covered — including its §5.0 flattening step — stops being used. That is the
"compiles, lints, passes schema validation, and is silently dead" failure mode §9 exists to
catch, arriving through the task board rather than through the code.

**2. T-001 is in flight and can create the collision within the hour.** Its declared files
include `client/src/main.jsx` and `client/src/routes/PreviewPage.jsx`. If it attaches the
store from `client/src/store/`, per the board, this repository ends up carrying both
directory trees with no statement of which one is real.

**3. Four tasks are scheduled as new work that already exists.** Checked against the files:

- T-008 — `initialCmsState()` already returns exactly `allSections`, `allSectionsCss`,
  `sectionNames`, `status`, `error`, `missing` (§5.2).
- T-009 — the §5.0 flattening and the §5.1 `missing` assertion are both implemented and
  covered by three tests plus the §9 assertion.
- T-010 — `auto`/`light`/`dark` all resolve, and never to `gray-400`.
- T-012 — `getHtml(value, fallback)` exists in `html.js` and its allow-list is tested.

The honest shape of Phase 1 for these four is **wiring, not writing**: install the
dependencies, swap the hand-rolled `cmsSlice` wrapper for a real `createSlice`, swap the
placeholder `<button>` for PrimeReact's `Button`, and mount the result. Both files say so in
their own header comments. The current titles ("Write the cms Redux slice…") describe work
that was already done in Phase 0, which is how a task gets marked done on the strength of
code somebody else wrote.

## Suggested fix

Two coherent directions. **Recommended: (a).**

**(a) Re-point the board at the files that exist.** Correct the six paths, and rewrite the
titles and `doneWhen` for T-008, T-009, T-010 and T-012 to describe the wiring that is
genuinely outstanding — real `createSlice`, a store attached at the app root, PrimeReact's
`Button`, and the component mounted at `/preview/Home`. This keeps the tested, twice-verified
artifacts untouched and leaves `npm test` green throughout.

**(b) Move the golden files to the board's paths** and update the imports in
`tests/golden.test.mjs`. Consistent, but it churns the only thing in this repository that
currently passes on a fresh clone with no install, and it buys nothing the first option does
not.

Either way, one thing is time-critical and independent of the choice: **T-001 should wire its
store imports to `client/src/redux/`**, because that is where the tested modules live today.
