## What is wrong

`state.cms.sectionNames` is declared by §5.2 as `{ [sectionId]: sectionName }` and
initialised to `{}` — and **nothing in the repository ever writes to it.** No reducer, no
action creator, no thunk, and no task's `files` list or `doneWhen` mentions it.

## Where

`client/src/redux/cmsSlice.js:22` is the sole occurrence of the identifier in the entire
repository:

```
grep -rn "sectionNames" --include=*.js --include=*.jsx --include=*.mjs . | grep -v node_modules
# -> client/src/redux/cmsSlice.js:22:    sectionNames: {},
```

`hydrateElements` populates `allSections` and `allSectionsCss`; `setMissing`, `setStatus` and
`setError` cover the other three keys. `sectionNames` is the one slice key with no writer.

## Why it matters

This is a **seam with no owner**, not a bug in existing code. T-050 — the preview shell, on
the studio-preview track — has to "render whichever generated module matches the current
section's `sectionId` and variation." That requires section documents, which come from
`GET /api/sections` (§13.4, task T-035, api-glassbox track). `sectionNames` is the declared
place for that data to land on the client, and no task on either track claims responsibility
for filling it.

`docs/GIT-PROTOCOL.md` names this exact failure class: a seam where "each will otherwise
assume the other owns it." §7 makes the same point about the generated-component mounting
seam, and the contract states it explicitly *because* it would otherwise fall between two
tracks. This one was not stated.

Nothing is broken today — T-050 is blocked behind T-011 and T-029, so the gap has not been
reached. It becomes real the moment the preview shell is built, which is squarely in Phase 3.

```
grep -rn "sectionNames" --include=*.js --include=*.jsx --include=*.mjs . | grep -v node_modules

node --input-type=module -e '

const els = JSON.parse(readFileSync("./seed/elements.json","utf8"));
console.log(JSON.stringify(hydrateElements(initialCmsState(), els, "Home").sectionNames));
# -> {}
'
```

## Suggested fix

**Name an owner, then add the writer.** Recommended shape:

1. A `sectionsHydrated` action and reducer case in the cms slice, filling
   `sectionNames[sectionId] = sectionName` from the bare array `GET /api/sections?pageName=`
   returns (§13.4).
2. A small `fetchSections({ pageName })` thunk beside `fetchElementsByIds`, following the
   same shape — one request, reduce the whole response, no per-id fetching.
3. Attach it to **T-050**'s `files` and `doneWhen` (the preview shell is the consumer and
   already depends on T-011), or split it into its own 25-minute task if the board prefers
   that granularity.

The alternative is to rule `sectionNames` **out of scope for the event** and say so in the
contract, if the preview will instead select its module from a section document fetched
ad hoc rather than from slice state. That is a legitimate answer — but it should be written
down, because §5.2 currently promises a key that nothing delivers, and the next person to
read the slice will assume it is populated.

Either way this is a board/contract decision rather than a repair, so it is flagged rather
than fixed. Related: [F-002](F-002.md) covers the same board's client-task path mismatches;
[F-003](F-003.md) covers the nested-card css slot, found in the same reading pass.
