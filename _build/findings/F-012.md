## What is wrong

Independently found the same defect T-117 already fixed, and initially filed this finding
without knowing that. Recorded here per the register's "never delete, mark superseded"
rule, not because the defect is still open.

`writeComponentFile.js` resolved `REPO_ROOT` with four `..` from `server/src/generate/`,
landing one level above the repository. Its own comment said "up 3 levels" — the comment
was right. Every generated component was written to a sibling `client/` tree that
`PreviewPage.jsx`'s `import.meta.glob('../sections/generated/*.jsx')` cannot see, so
`/preview/Home` rendered a "Missing component file" box for every section while generation
itself reported `200 OK` and stage 7 recorded success.

Reproduced independently against `main@d3543e3` (pre-rebase): 31 orphaned files in the
stray tree, a live `POST /api/generate` landing outside the repo, and
`tests/write-component-file.test.mjs` computing the correct `GENERATED_DIR` at line 56 and
never asserting against it — ten tests passing against a wrong root.

## Why this is marked superseded, not fixed

`git log` shows T-117 (Mohit Gupta, `161a135`) landed the identical one-line fix — `..','..','..','..'` to `'..','..','..'` — at **2026-08-22 02:43:46 +0530**, before this
finding was drafted. T-118 (`ae38877`) followed with a scoped
`client/src/sections/generated/.gitignore` and
`tests/generated-sections-are-not-committed.test.mjs`, which also resolves the housekeeping
problem this finding's investigation separately ran into (test runs dirtying the working
tree with fixture components).

T-117's own regression test, `tests/write-component-file-path.test.mjs`, is more thorough
than the fix drafted alongside this finding: it asserts both that the file lands inside the
repo *and* that it is absent from the parent — the exact shape of the bug, not just the
positive case.

A duplicate fix and a duplicate strengthened assertion were drafted locally against this
defect, then discarded via `git checkout --` once T-117/T-118 were discovered upstream,
and `git pull --rebase` was used to take main's version rather than carry a second copy of
the same one-line change. No code changes from this investigation were kept.
