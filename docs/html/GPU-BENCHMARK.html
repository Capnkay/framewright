GPU Benchmark

Roughly 2–3 hours, most of it downloading. Only Step 5 actually matters — everything before it is setup.

Why you are doing this

We are building something that turns a wireframe picture into React code. One stage has to look at a layout and answer: where is the headline, where is the image, where is the button?

We chose Florence-2 for that, because you can hand it the words you are looking for — "call to action button" — and it hands back a box. No training required.

The problem: every published result for this model is on rendered screenshots and photographs. Our real input is low-fidelity wireframes. Nobody has published a number for that. So we genuinely do not know if it works.

Prefer being talked through it? Upload docs/GPU-BENCHMARK.md to ChatGPT or Claude and say "walk me through this one step at a time." The file briefs the assistant too.

Before you start

  • The laptop with the RTX 3050
  • Python 3.10, 3.11 or 3.12
  • ~10 GB free disk, and internet

The steps

0
Confirm the GPU is really there 
nvidia-smi
python --version

Good: a table with your GPU name. Write down the total memory — something like 4096MiB.
Bad: command not found → install the NVIDIA driver, reboot, retry.

1
Clean workspace — outside the project repo 
mkdir gpu-test
cd gpu-test
python -m venv .venv

# PowerShell  .venv\Scripts\Activate.ps1
# Git Bash   source .venv/Scripts/activate
# mac/Linux  source .venv/bin/activate

Your prompt must now start with (.venv). If it does not, stop and fix it — everything after depends on it.

2
PyTorch with CUDA — big download, ~2.5 GB 
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124

If it complains about CUDA versions, check the version in the top-right of nvidia-smi and swap cu124 for cu121 or cu118. Do not let it install the CPU-only build — that silently defeats the whole test.

3
Confirm PyTorch can see the GPU — save as check.py 
import torch
print("torch version :", torch.__version__)
print("CUDA available:", torch.cuda.is_available())
if torch.cuda.is_available():
    print("device        :", torch.cuda.get_device_name(0))
    total = torch.cuda.get_device_properties(0).total_memory / 1024**3
    print(f"total VRAM    : {total:.2f} GB")

Good: CUDA available: True. Bad: False → you got the CPU build. Uninstall and redo step 2.

4
Model libraries 
pip install transformers pillow einops timm accelerate
5
The actual test

Everything above was setup. This is what the team is waiting on.

5a — get a real wireframe. Do not use a polished screenshot. We need to know how it copes with the messy input we will actually get.

  1. Draw one on paper — big rectangle left (image); on the right: a small label, a big headline, a smaller subheading, a paragraph, three little boxes in a row, a button. Photograph it. This is the most valuable version of the test.
  2. A low-fidelity Figma or whiteboard wireframe
  3. Fallback only: a screenshot of a real website hero

Save it as wireframe.png in gpu-test.

5b — run it. Use the full test.py from docs/GPU-BENCHMARK.md. It asks the model for each of the seven things we actually need to find, and prints a box, a time, and the peak VRAM.

5c — judge it honestly. This is the whole exercise.

For each of the seven, open your image and ask: is that box actually on the right thing? Count how many of the seven it got right.

A box that came back but landed on the wrong element is a wrong answer, not a partial one. Please do not tune the test until it looks good. Report what actually happened.

6
OCR — optional, if you have time 
pip install paddlepaddle paddleocr

Just record whether it installs cleanly on Windows and whether it reads your text. PaddleOCR on Windows is known to be awkward. If it fights you for more than 30 minutes, stop and write down what happened — that is a useful result too. EasyOCR is our fallback.

What your number means

Correct out of 7What we do
6–7Plan stands. Perception runs locally as designed.
4–5Plan stands, plus human-in-the-loop correction for low-confidence regions — which we designed for anyway.
2–3We rethink. Probably a hosted vision model for this stage, with Florence-2 as the local fallback.
0–1Real change of plan — and much better to know now. The pipeline still works from prompt and code input; the wireframe path becomes the weakest of the three rather than the flagship.
There is no wrong answer here, only an unknown one. A low score is a genuinely useful result — it redirects three people's work before they spend two days on it.

Do not

  • Do not install ultralytics or use YOLOv8. Its licence has a network clause our architecture triggers. It is on the forbidden list.
  • Do not use LayoutLMv3. The code is MIT but the weights are non-commercial.
  • Do not commit anything from this folder. Model weights are hundreds of megabytes and must never enter the repository.
  • Do not run this inside the project repo. Keep gpu-test separate.
