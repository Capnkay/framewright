The harness

Everything that exists before the build starts, so that six people on six machines can work at once without colliding, losing work, or drifting from the spec.

You need to remember one command. Everything below happens behind it. continue build

How a session works

  1. Pull, so everyone else's claims land first
  2. The board shows who holds what, and what's blocked
  3. You're handed the next task whose dependencies are met
  4. The task names the contract sections it must satisfy. Open them — they are the requirement
  5. Claim it. The claim pushes instantly, so nobody races you
  6. Build it
  7. Mark it done — a verification runs and decides, not an opinion
  8. Commit with the task id. Push

Two design choices worth knowing

One file per claim. Different tasks touch different files and merge silently. Two people claiming the same task makes a git conflict — the one collision you want loud rather than hidden.

One journal per person. Nobody ever conflicts on the log, however much they write.

Session died mid-task? Your claim stands with a timestamp, and the next person sees it's stale and can take it over deliberately. Nothing is lost quietly.

How the pieces connect

One canonical rulebook, four doors into it. Whichever tool you use — Claude Code, Antigravity, Cursor, Copilot, or a human with a terminal — you reach the same instructions. AGENTS.md is an open standard stewarded by the Linux Foundation; the others point at it rather than repeating it, so there is nothing to keep in sync.

Two rules that decide our score

The store has to be alive

Every field renders as value || "DEFAULT". With a dead data store the page looks pixel-identical to a working one — right copy, right layout, right responsive behaviour. It compiles, lints, and passes schema checks.

It fails only when someone changes a value and nothing moves — which is exactly what a judge is told to do.

A dead store caps us at 40 out of 100. An automated check catches it and runs on every commit. Never disable it.

Some of the code looks wrong and is graded

Do not tidy any of this. Tidying it costs the 25-point criterion:

  • dangerouslySetInnerHTML with a default fallback
  • dynamicStyle / dynamicStyle2 marker classes — look dead, aren't
  • the const ids map — don't inline it, don't extract it
  • CSS applied via getElementById — not a style prop

Every one of them is inspected by a judge.

Where help is useful

  • Confirm which file Antigravity reads. Its documentation describes .agents/rules/; other sources say a root AGENTS.md. We support both. Five-minute check: put a distinctive phrase in one, ask Antigravity about it, note which it knows.
  • Check the nine Studio requirements (FR-G01–G09) against the original brief. Our task list works from a nine-item reading; the Studio is worth 10 points, so it's worth ten minutes of confirmation.
  • GitHub and Vercel. The docs site needs no secrets — output directory is docs/html.
  • Anything that surprises you. Write it into docs/EDGE-CASES.md while it's fresh. Twenty minutes lost to something confusing is worth five minutes of writing it down.
