What the harness is, and what's in it

You asked for a context file so every agent on every device has the right context. You were right that something was missing — read on for what it was, and what it's now called.

Short version: the content you wanted already existed, but only Claude Code could find it. That gap is now closed with AGENTS.md — which turns out to be a real cross-tool standard, not a name we invented. Keep poking at gaps; this one was worth finding.

Your question, answered honestly

“Do all agents have context on build progress?”

The content: yes, and it can't go stale. _build/STATE.md is generated from the task board every time anyone finishes a task. Nobody maintains it by hand, so it cannot drift from reality.

The discoverability: no — and you found a real hole. Our rules lived in CLAUDE.md, which Claude Code auto-loads and nothing else does. Antigravity is our main executor. Every rule we wrote was invisible to it.

What we did about it

AGENTS.md at the repo root is now the one canonical instruction file. It's an open standard backed by the Linux Foundation since Dec 2025, and it's read by Cursor, Copilot, Gemini CLI, Codex and Devin.

CLAUDE.md is now three lines of import plus Claude-specific notes. That's Anthropic's own documented recommendation, not our invention.

.agents/rules/ carries the same rules for Antigravity, because its docs describe that folder and do not mention a root AGENTS.md — third-party blogs say they do, the official docs disagree. We covered both rather than betting.

One thing we deliberately did NOT do: no file restates build progress. A hand-written progress summary sitting next to a generated board drifts within hours and then quietly lies to whoever reads it next. The new files are routers — they point at the generated truth. They are not a second copy of it.

Why the register is the part to actually read

It's a list of things that were wrong and got caught. A few, so you can see what kind of thing it catches:

  • Nested card IDs had no store keys. Every stat card would have rendered its default forever while everything else worked. Nothing would have looked broken.
  • Regeneration preserved IDs but overwrote content — so the judge's typed headline would vanish during the exact demo moment built around it surviving.
  • Line endings broke the integrity check — on a fresh clone all 8 entries failed. Your first commit would have been blocked by our own hook.
  • The protocol contradicted itself — finishing a task made you unable to commit it. Every task. Every person.
  • Phase 0.4 was marked done and wasn't. That's the gap you were pointing at.

None of these were visible from reading the code. They surfaced from cloning the repo and behaving like someone who'd never seen it — which is close to what you were doing when you asked your question.
