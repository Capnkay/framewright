Framewright — Team Rules

Wireframe / code / prompt → CMS-ready React. React + Node are mandatory. Everything here fits on one page on purpose. Read it once, keep it open.

Every session starts the same way

Type: continue build
  1. git pull --rebase — other people's claims land first.
  2. baton status — who holds what, what's blocked.
  3. baton next — your next task.
  4. Open the contract sections the task names. The title is a label. The contract is the spec.
  5. baton claim T-0xx → push the claim immediately.
  6. Build it.
  7. baton done T-0xx — runs the check. Failing check = not done.
  8. Commit with the task id in the message, and push.

Session died mid-task? Your claim stands with a timestamp. Someone runs baton takeover. Nothing is lost silently.
Two people claimed the same task? Git raises a conflict. That's the system working — talk, keep one.

The trap that decides our score

Every text node renders as data?.[id] || "DEFAULT". That fallback is a mask. With a completely dead store the page looks pixel-identical to a working one — right copy, right layout, right responsive behaviour. It compiles, lints, and passes schema checks.

It fails only when someone changes a value and nothing moves — which is exactly what the judge is told to do.

A dead store caps us at 40/100. The automated store-liveness check is the only thing that catches it. Never disable it.

These look like bad code. They are graded.

Do not "clean up" any of it. Cleaning it up costs the 25-point criterion.

  • dangerouslySetInnerHTML with a default fallback — required
  • dynamicStyle / dynamicStyle2 marker classes — look dead, aren't
  • the const ids map — don't inline it, don't extract it
  • CSS applied via getElementById in an effect — not a style prop
  • every editable node carries an id, cards included

Eight rules

  1. The contract wins. Code disagrees with docs/CONTRACT.md? The code is the bug. Think the contract is wrong? Fix it and log it in corrections/REGISTER.md. Never quietly diverge.
  2. Prove the store is alive. See the red box.
  3. IDs come from the API. 10 digits, central, persisted. Never Math.random(), Date.now(), uuid, nanoid. Never from a model.
  4. The deterministic path always works. Nothing may make generation require a key, a GPU, or a network.
  5. Producer ≠ verifier. Nothing is done until something that didn't build it has checked it.
  6. No secret ever reaches a commit. Hooks are law. A hook blocking legitimate work gets fixed and logged, never weakened.
  7. One task, one claim, one commit message with its id.
  8. Every claim carries a source — and says whether it was verified or just reported.

Nothing loose at the repo root. No scratch files, no screenshots, no one-off scripts. If it has no home, it needs a folder before it needs a file.
