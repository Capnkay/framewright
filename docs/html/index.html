Every session, one command

continue build

It pulls, shows you the board, and hands you the next task whose dependencies are met — along with the contract sections that task has to satisfy. You claim it, build it, and mark it done, at which point a real check runs and decides. Then commit with the task id and push.

Two rules that decide our score

The store has to be alive

Every field renders as value || "DEFAULT", so a page with a dead data store looks identical to a working one. It only fails when someone changes a value and nothing moves — which is exactly what a judge is told to do. Caps us at 40 out of 100. An automated check catches it. Never disable it.

Some code looks wrong and is graded

Don't tidy dangerouslySetInnerHTML, the dynamicStyle classes, the const ids map, or CSS applied via getElementById. Every one is inspected by a judge. Tidying them costs 25 points.
