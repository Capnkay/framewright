What it actually does

Every element gets a default value and a CMS-editable flag, and statBadges gets a loop shape: how many cards, and how many fields inside each one. The fields-per-item count must be uniform (§4) even when the wireframe shows one badge with an icon and another without — this stage normalises that before it ever reaches an element document. It does not allocate the field IDs those loop items will eventually need; that happens later, in the API.

Why everything is editable by default

ApproachVerdictReason
Every field CMS-editable by defaultchosen The 25-point criterion is CMS-bindability. A static text node can't be patched or previewed as changed — it scores nothing against the demo's central moment (§9, §13.2).
Hard-code "decorative" copy as static JSXrejected Looks identical until a judge tries to edit it. Nothing in a wireframe distinguishes "safe to hard-code" from "must be editable," so the safe default is to make everything a field.
Card fields start with an empty defaultrejected An empty default defeats the data?.[id] || "DEFAULT" fallback (§9) — the store-liveness safety net depends on every field having real fallback text.
Every nested fieldIdN each loop field gets will need its own store key downstream (§5.0) — so the item count and fieldsPerItem decided right here is what determines whether the cards can ever hydrate. Get this shape wrong and no later fix can save it without a fresh section.

How it fails

FailureWhat happens
Card count disagrees with the prompt§6: prompt wins card count. Skip that check here and a "four stats" request silently defaults to 3, and the demo fails live.
Uneven fields per item§4 rule 3 requires uniformity across the loop, recorded as cards.fieldsPerItem. A wireframe with one icon and not another must be normalised to match.
Default copy left emptyDefeats the || "DEFAULT" fallback (§9) — the field renders nothing until the store hydrates, invisibly, which is harder to catch than a stray placeholder string.
A field the demo expects to edit is marked non-editableUnverified. The wireframe alone doesn't say which fields a demo script wants edited live; this stage assumes "everything," per the choice above.
