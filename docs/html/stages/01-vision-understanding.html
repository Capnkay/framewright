Multi-Modal Understanding

Vision Understanding

Turn a picture of a layout into labelled regions with roles.

IN

A normalised wireframe image, plus the label set we are looking for.
→

OUT

Boxes, roles, text, and a confidence per region.

What it actually does

Two models look at the same picture and answer different questions. One finds where things are and what they are; the other finds what they say. Fusion overlaps the two: a box the grounding model called a button, containing the text "FIND A WORKOUT", becomes one region with a role, a position, and its words.

Out

// one entry per detected region — no fieldId, ever (§1)
{
  "elementName": "ctaButton",
  "role":        "action",
  "text":        "FIND A WORKOUT",
  "bbox":        [500, 400, 200, 60],   // normalised space (§6)
  "confidence":  0.91
}

Which model, and why that one

OptionVerdictReason
Contour detection
OpenCV, Apache-2.0		chosen A wireframe is rectangles and text. Contours find rectangles in a line drawing almost trivially — the worst case for a photo-trained network is close to the best case for classical CV. No weights, no VRAM, no licence question. Upgrade path: a detector trained on wireframes we render from our own IR schema, giving unlimited data with perfect ground-truth boxes.
Open-vocabulary grounding
Florence-2, MIT		measured, rejectedMeasured twice on our own hardware, both task families. 0 of 7 each time. Asked to detect objects unprompted it returned one box labelled "whiteboard". VRAM was never the issue (peak 1.76 GB of 6). See the note below.
YOLOv8rejectedPretrained on COCO — person, car, chair. No UI classes at all. And AGPL with a network clause, which our architecture triggers.
LayoutLMv3rejectedA forms-and-receipts model. Cannot emit web-section roles without retraining. Its weights are non-commercial even though the code repo is MIT.
DonutrejectedEmits structured text, not boxes. We need coordinates.
We measured this instead of assuming it. The approved diagram names three models for this box, and none can produce our label set without retraining — verified against primary sources. We then tested the one that theoretically could, on our own wireframe, on our own GPU. It is not failing to see the image — it is seeing exactly one object where we need seven. Unprompted, it called our wireframe "a hand-drawn website layout", which is the correct answer to the question it was trained to answer. It simply has no notion that a wireframe decomposes into UI components. That is a training-distribution gap, not a prompting problem — confirmed across both task families. Numbers in docs/BENCHMARK-RESULTS.md.

How it fails

FailureWhat happens
Sketch-fidelity inputMeasured, definitively. A state-of-the-art vision model scored 0 of 7 on exactly this input, twice, across both task families. This is why the stage is classical CV — not a preference, a finding.
Two regions overlapFusion assigns the text to the wrong one. Both drop below 0.60 and escalate.
Model unreachableStage marked degraded. The pipeline continues on the prompt path. Never a crash.
Confident and wrongThe dangerous one. High confidence, wrong role. Only the golden-file diff catches it.

What confidence means here

≥ 0.85accept
0.60–0.85verify, record a warning
< 0.60ask a human, or fall through to the template

A region that did not come from an image carries null, never a made-up number.

What it must not break

  • §1 — this stage never allocates a fieldId. Regions come back identified by name and position only. IDs belong to the Node API.
  • §6 — bbox is in normalised image space, and the normaliser's transform must be recorded in the stage-2 trace. Without it, nobody but its author can map a box back onto the upload — and they are on a different machine.
  • §12 — output goes back inline in the HTTP response. This service writes no files; artifacts are owned by Node.
  • §11 — one immutable trace record, with the model name and the device.
