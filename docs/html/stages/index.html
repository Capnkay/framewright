Stage 2 — Preprocessing & Normalisation (Python)

No dedicated card among the 13 covers this stage on its own — it is documented inline, as the first box of Card 1's own diagram ("normalised image"), and its output-shape requirement is fixed by docs/CONTRACT.md §6: the normaliser's transform (scale, offsetX, offsetY, width, height) must be recorded in the stage-2 trace, or a bbox downstream is unusable by anyone who did not write the normaliser.

Stage 3 — Multi-Modal Understanding (Python)

CardWhat it doesTrack
01 — Vision Understanding Turn a picture of a layout into labelled regions with roles. Perception
02 — Code Understanding Parse pasted JSX/TSX to an AST and extract only text, image and button nodes — never execute it. Floating — whichever track clears first (ROADMAP.md Phase 3)
03 — Prompt Understanding Turn a typed prompt into section type, card count, colour and CTA — with a hosted model, or keyword extraction with none. Everyone — built pre-split in Phase 2
04 — Cross-Modal Alignment When wireframe, code and prompt disagree, apply the documented conflict-resolution order and record why (§6). API & Glass Box
05 — Confidence Scoring Score every region 0.0–1.0, or null when it did not come from an image — and decide accept, verify, or escalate. Perception
