Multi-Modal Understanding

Prompt Understanding

Turn a sentence into an IR fragment — with or without an API key.

IN

A natural-language prompt, e.g. "make the CTA green and use four stats".
→

OUT

Section type, layout hints, card count, accent colour, CTA label, copy.

What it actually does

If a hosted model and a key are available, it runs a structured-output call constrained to the IR schema. If not — no key, no network, or the call fails — a keyword-and-template extractor runs instead: it looks for colour words, numbers before "stat"/"card", and a handful of section-type cues. Either path produces the same shape and is validated the same way before it reaches §4's conflict resolution.

Out

// prompt: "make the CTA green and use four stats" — parsed with no API key present
{
  "sectionType": "split-hero",
  "cards": { "count": 4 },
  "theme": { "accent": "green-500" },
  "elements": [
    { "elementName": "ctaButton", "sourceOf": "prompt", "confidence": null }
  ],
  "warnings": ["keyword path used: no LLM_API_KEY set"]
}

Which path, and why both are required

OptionVerdictReason
Hosted model, structured outputchosen (primary) Constrained to the IR schema, it reads nuance a keyword list can't — "a bit more playful", implied section type. Best quality when a key is present.
Keyword / template extractionchosen (mandatory fallback) Regex for colour words and numbers, a small lookup for section type. Lower quality, but it is the only reason "works with no API key" is true rather than claimed.
Free-form generationrejectedAn unconstrained model reply can't be validated against the IR schema — there is no way to tell a good answer from a plausible-looking bad one before it reaches generation.
The keyword path is not a degraded stub — it's a hard requirement. The working agreement states it plainly: prompt mode and the CMS contract must stay fully demonstrable with the perception service stopped and LLM_API_KEY unset. If the hosted path were the only one, "no key needed" would be false the moment someone tested it.

How it fails

FailureWhat happens
No key presentFalls straight to the keyword path. Recorded in warnings, never a silent quality drop.
Ambiguous promptMissing fields take their contract defaults (e.g. variations: "1"); each default used is logged.
Prompt contradicts the wireframeNot an error — §6's conflict order resolves it: prompt wins copy/colour/CTA/count, wireframe wins layout. The override is recorded in warnings.
Absurd card count ("fifty stats")Unverified. The contract sets no ceiling on cards.count — nothing in §6 or §13.1 defines a maximum, so this card cannot claim one is enforced here.

What "no key needed" actually covers

  • Prompt mode of POST /api/generate (§13.1) always returns a valid fragment
  • No network call is attempted when no key is configured
  • Output still validates against the same IR schema either way

What it must not break

  • §6 — the emitted fragment is real IR shape: no fieldId anywhere (the API mints those later), and every field it sets is one the conflict-resolution order actually reads.
  • §13.1 — prompt is one of the accepted inputs to POST /api/generate; this stage is what that mode depends on to produce anything at all.
