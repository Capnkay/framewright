Model Orchestration

Model Orchestrator

One door for every model call, so five call sites never quietly grow five different retry policies.

IN

A stage's request for a model call: which job — perception grounding, OCR, or hosted code generation — what input, and its content hash.
→

OUT

A model result and a written trace record, or a degraded stage status. Never a crash.

What it actually does

Every stage that needs a model — perception grounding, OCR, or the hosted code-generation call — goes through this one door instead of five. It hashes the input, checks the cache, and only calls out on a miss, wrapped in one timeout and one bounded retry policy. Every call, hit or miss, writes an immutable trace record naming the model that produced it, so a result can be explained later. A model that never answers does not fail the job — it marks the stage degraded and the pipeline keeps moving on the deterministic path.

OptionVerdictReason
One orchestrator

The model most teams would reach for on a modest GPU is licensed against exactly this use. Qwen2.5-Coder-3B's small footprint is the trap, not a feature — the fix costs VRAM, not code.

How it fails

FailureWhat happens
Hosted API returns 401Bad or missing key. No retry — retrying an auth failure just spends the rate limit. Stage marked failed, warning recorded.
Hosted API returns 429Retried with backoff, bounded. Exhausted retries degrade the stage rather than fail the job.
GPU machine asleepIdentical handling to a timeout: no 200 from /perceive, stage marked degraded, pipeline continues on the deterministic path (§12).
Cached result for a changed inputA cache keyed on job id instead of content hash returns stale output — a key bug, not accepted behaviour.
Non-deterministic model outputTwo runs of the same job can differ. Downstream validation treats every model result as untrusted regardless of cache; the trace record stays reproducible even when the output does not.

Append-only. A retry adds a record; it never edits the old one.

What it must not break

  • §11 — every model call writes one append-only stage record naming the model that ran, or null if none did. Retries add records; they never overwrite one.
  • §11.1 — status is a closed set; degraded means the job still succeeds and the stage carries a warning, never a thrown error.
  • §12 — the Node↔Python boundary is one endpoint, /perceive, and degradation across it is mandatory: prompt mode and the CMS contract must stay demonstrable with the perception service stopped, the GPU absent, and no network.
