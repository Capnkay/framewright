Code Generation & Assembly

Turn the IR into a React component that satisfies all fourteen rules — by construction, not by luck.

IN

The finished IR (§6) — layout, theme, cards, elements, and the ID policy.
→

OUT

A .jsx section component satisfying R1–R14, written to a unique file.

What it actually does

Two paths produce the same shape. The deterministic emitter walks the IR and fills a template — no network, no key, correct by construction because it satisfies the contract mechanically. The hosted-model path asks a model to write richer JSX from the same IR; that output is then validated and, on failure, regenerated or replaced by the deterministic emitter. Either path writes one unique file per section, ID, and variation, so a second variation never overwrites the first.

Out

// generated component excerpt — satisfies R1, R2, R3
const ids = {
  headlineMain: "2000000003",
  ctaButton:    "2000000007",
  statBadges:   "2000000006"
};

useEffect(() => {
  dispatch(fetchElementsByIds({
    // every field ID in the tree, nested card IDs included
    elementIds: [...Object.values(ids), "3000000001", "3000000002"],
    pageName
  }));
}, [pageName]);

Which path, and why that one

OptionVerdictReason
Deterministic emitter
primary path		chosen Satisfies R1–R14 by construction — no key, no network, latency is a template fill. Must still work with the perception service down and LLM_API_KEY unset.
Hosted model, as an enhancementchosen Produces richer, more varied JSX from the same IR — but every output is validated against the same rules before it ships, and a failure regenerates or falls back to the emitter.
Hosted model as the only pathrejectedTies every generation to a key, a network call, and a non-deterministic result — none of which the §12 degradation guarantee allows to be load-bearing.
Copy the brief's reference component verbatimrejectedIts R9 guard hard-codes .length === 3. A four-stat regeneration then silently renders three stale defaults — compiling, linting, and wrong.
Do not "clean up" the odd parts. dangerouslySetInnerHTML, dynamicStyle/dynamicStyle2, the const ids map, and CSS applied via getElementById all look like debt. Every one is graded (§7). Improving them costs the 25-point code-quality criterion, not gains it.

How it fails

FailureWhat happens
Invalid JSX from the modelCaught by validation (Card 12), triggers a bounded regeneration, then falls back to the deterministic emitter.
Fixed filename reusedVariation 2 overwrites variation 1 on disk; the preview's Vite glob then serves only the survivor.
Model omits nested card IDs from the mount fetchCompiles and renders defaults perfectly. Card fields never hydrate — invisible until someone edits a card.
Model invents a helper importBuild fails outright — fetchElementsByIds and getSectionTextContrastClass must resolve to real files in this repo.

The mounting seam (§7)

filename<SectionName>-<sectionId>-v<variation>.jsx
discoveryimport.meta.glob('./sections/generated/*.jsx', {eager:true})
selectionby sectionId + variation on the section doc

No restart, no manifest — Vite HMR picks it up.

What it must not break

  • §7 — all fourteen rules, R1–R14. A component missing even one (the R9 length guard, most often) is a contract failure, not a style note.
  • §7 mounting seam — a unique filename per section, sectionId, and variation. A fixed name silently destroys a prior variation, and the Vite eager glob is how the preview finds the file at all.
  • §6 — the component is a pure read of the IR; nothing here allocates an ID or invents a field not present in it.
