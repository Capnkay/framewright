Multi-Modal Understanding

Code Understanding

Turn pasted React/JSX into the same element shape the other two inputs produce.

IN

Pasted React/JSX source, plus an existing ids map when this is a regeneration.
→

OUT

IR elements — tag, order, content — with any repeating children folded into a Cards loop.

What it actually does

The AST is walked once. Text, image and button nodes become elements directly. Siblings that repeat the same tag and prop shape — three <div>s each holding a number and a label — become one Cards element with a loop, per §4. If an ids map came in with the request, matching element names keep their existing field IDs instead of getting new ones (§6, idPolicy.mode: preserve). The source is never run — only parsed.

Which parser, and why that one

OptionVerdictReason
@babel/parser
jsx + typescript plugins, errorRecovery		chosen Produces a real AST for JSX, tolerates a pasted fragment that doesn't fully compile, and never runs a single line of the input.
Regex extractionrejectedCannot handle nesting — a button inside a card inside a map. Breaks on the first component more complex than the reference one.
eval / new FunctionrejectedExecutes attacker-controlled code in the API process. Forbidden outright by §8.
Node's vm modulerejectedLooks like a sandbox and isn't one — §8 states plainly that vm.runInNewContext is not a security boundary. Same for a spawned child process running the pasted file.
Pasted code is parsed, never executed — no exceptions, no "just this once" for a trusted-looking snippet. §8 names eval, new Function, require() of a written temp file, vm.runInNewContext and a child process as forbidden by name, because each one has been proposed as a shortcut before.

How it fails

FailureWhat happens
Malformed JSXerrorRecovery parses what it can; unparseable nodes are dropped and recorded as a warning, not a crash.
Ambiguous repeatTwo siblings look alike but aren't a loop (e.g. differing child counts). The heuristic guesses and logs a warning rather than silently choosing.
Unknown IDs in an incoming mapAn ids entry outside the sanctioned 2000…/3000… ranges is rejected; that field is treated as new and gets a freshly allocated ID.
Fragment, not a componentNo export default, no wrapping element — the walk still extracts what it finds, but the card is escalated for human review rather than assumed complete.

Repeat-detection heuristic

  • Consecutive JSX siblings, same tag, same prop shape
  • Needs two or more to count as a loop
  • Field count per item must be uniform — recorded as cards.fieldsPerItem
  • Loop length becomes cards.count, never hard-coded to 3

What it must not break

  • §8 — pasted code is parsed, never executed. No eval, no vm, no child process, whatever the input looks like.
  • §6 — when an ids map is supplied, idPolicy.mode is preserve: matching element names keep their field IDs, and card slots preserve positionally by index.
  • §4 — a detected repeat becomes a Cards element with a uniform fieldsPerItem and a count taken from what was actually found, never assumed to be three.
